# Agentic Hub — البيانات وسجل البحث

موقع عربي RTL مبني بـ React + TypeScript + Vite. يجمع مكتبة 26 مصدر بيانات، دليل تدريب الوكلاء، محاكيًا تعليميًا، وسجلًا موثّقًا لتجارب Weight-Space Programming وSEAL على Qwen.

## تحديث 16 نوفمبر 2026

أضيفت صفحة `/research-lab` مع 10 محطات، بحث وتصفية، حالة التجربة الحالية، خطة الاستكمال، نسخ ملخص Cursor، وتنزيل ملخص الحالة. مكتبة البيانات والمفضلة والمقارنة والمحاكي باقية.

**آخر حالة بحسب تقارير صاحب المشروع:** خطوة LoRA حقيقية غيّرت المحوّل. فحص ثبات الأساس عبر أسماء تغليف PEFT أوقف العملية قبل الاستعادة. SEAL الداخلية التالية والخارجية لم تنفذا. لا دليل على تحسين ذاتي عام. هذه لقطة تحريرية؛ الموقع لا يتصل بـ Colab ولا يشغّل النموذج.

## تشغيل واختبار

Node.js 22:

```bash
npm ci
npm test
npm run build
npm run dev
```

مجلد الإنتاج: `dist`. ملفات `dist` و`node_modules` لا تُرفع إلى GitHub؛ Cloudflare يبنيها من المصدر.

## تحديث المستودع المتصل بالفعل بـ Cloudflare

1. فك ضغط الحزمة، وافتح مجلد `agentic-dataset-hub-main`.
2. انسخ **محتويات المجلد** إلى جذر نسخة المستودع الحالي، حيث `package.json`. لا تضع المجلد كله داخل مجلد فرعي بالمستودع.
3. احتفظ بمجلد `.git` في نسختك المحلية وبأسرار GitHub وإعدادات Cloudflare. لا ترفع أي tokens.
4. شغّل الاختبارات والبناء، ثم راجع diff وcommit وpush إلى الفرع الذي ينشره مشروعك (الـworkflow الحالي يستخدم `main`).
5. افحص سجل النشر ثم افتح `/research-lab` وحدّثه مباشرة للتأكد من عمل المسارات.

المشروع يحتفظ بملف `.github/workflows/deploy.yml` الأصلي دون تعديل. ينشر إلى Pages project المسمى `agentic-dataset-hub`، ويحتوي شرط المستودع `mohamedahmedhimdan/agentic-dataset-hub`. إذا كنت تستخدم هذا المسار بالفعل فلا تغيّر الأسرار أو اسم المشروع.

إذا كنت تعتمد على تكامل Cloudflare Pages مع GitHub مباشرة، إعدادات المشروع الحالية المطلوبة: أمر البناء `npm run build` ومجلد المخرجات `dist` وجذر المستودع. لا تُنشئ مشروع Cloudflare جديدًا. إن كان مسارا النشر مفعّلين معًا، اختر مسارًا واحدًا من إعداداتك لتجنب نشرين لكل push؛ لم نغيّر ذلك تلقائيًا.

الـworkflow الأصلي يحتاج `CLOUDFLARE_API_TOKEN` و`CLOUDFLARE_ACCOUNT_ID` في GitHub Secrets إذا كنت تعتمد عليه. لا يحتاج الموقع ذاته إلى API أو قاعدة بيانات.

يمكن رفع المصدر من GitHub: **Add file → Upload files**، مع رفع ملفات ومجلدات المصدر بعد فك الضغط، وليس ZIP نفسه. رفع الملفات وحده لا يحذف ملفًا قديمًا موجودًا أصلًا؛ يمكن حذف `agentic-dataset-hub-source.zip` القديم من المستودع لأنه نسخة مصدر قديمة غير مستخدمة.

## أين تُحدّث المحتوى لاحقًا؟

- `src/research/progress.json`: الحالة والبيئة والمحطات وخطوات الاستكمال.
- `src/research/ResearchLab.tsx`: واجهة سجل البحث وصياغة التسليم إلى Cursor.
- `src/research/research.css`: تصميم السجل المستجيب للشاشات.
- `public/research/PROJECT_STATUS.md`: التقرير القابل للتنزيل؛ حدّثه مع البيانات.
- `public/research/progress.json`: نسخة التصدير الثابتة؛ يجب أن تطابق المصدر (الاختبار يتحقق).
- `docs/UPDATE_NOTES.md`: التغييرات وحدود التحقق.

أضف محطة جديدة بدل تغيير نتيجة تشغيل قديم. ميّز دائمًا بين: عارض مبرمج، فحص تدريب، تجربة تكيّف، واختبار نهائي مستقل. لا تعتبر علامات قائمة القراءة الشخصية إتمامًا للتجارب.

## المسارات والمحتوى

المفضلة والمقارنة وتقدم القراءة تستخدم localStorage في متصفح المستخدم. يحتوي `public/_redirects` على fallback للمسارات الداخلية. لا توجد أوزان نماذج أو سجلات Colab الخام أو مفاتيح في الحزمة. روابط مصادر البحث مراجع خارجية، وليست إثباتًا لنتائج مشروعنا. تصنيفات وترخيص بيانات المكتبة تحتاج مراجعة المصادر الأصلية قبل الاستخدام.
